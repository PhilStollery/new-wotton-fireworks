Wotton Fireworks 2026 Tito integration package v23
===================================================

PURPOSE
-------
V23 is cumulative over v22. It fixes the shared Activity counting/reveal logic,
parking reserve calculation and selector presentation, and reorganises the
public ticket journey into Prices + three booking steps.

V23 TEST CHECKLIST
------------------
1. Navigation should read: What's on / Prices / Tickets / Plan your visit / FAQ.
2. Prices should show a table before the Tickets section containing every
   customer-facing ticket release, its current Tito price, allocation and date.
3. Tickets should be split into three panels:
   Step 1 Book for Wotton-under-Edge
   Step 2 Decide how you'll get there
   Step 3 Get your tickets
4. Travel options should show no orange price text. Selection labels must remain
   Walking / Bus from Wotton / Bus from Charfield / Driving and the explanatory
   note must say the choice is only for demand planning.
5. Pre-school should have only the header "Everyone attending needs a ticket" —
   no event-capacity number and no explanatory sentence in the header.
6. Super Saver and Advance counters must use the remaining number from their Tito
   Activities. Standard must use the remaining number from the overall event
   Activity.
7. Paid-band headers should read e.g. "Super Saver Tickets" with the right-hand
   status "### available until 5pm Monday 5th October" or "Sold Out".
8. Select tickets until the current band has no local headroom. The next band
   should reveal. One more ticket should be moved into the matching ticket type
   in the next band. Repeat at the Advance/Standard boundary.
9. Parking should begin with 120 general spaces. Blue Badge selections up to the
   protected 30 should not reduce that figure; selections/bookings above 30 should.
10. The Blue Badge group header must not contain the valid-badge warning. The
    Blue Badge ticket row must state that a valid Blue Badge must be displayed.
11. Confirm the previous child-accompaniment wording is absent from the FAQ and ticket terms.
12. Complete a test purchase. Checkout/payment behaviour must remain Tito's.
13. Confirm the post-purchase panel tells the customer to expect ticket emails
    from Tito and that optional responses still save.

IMPORTANT
---------
Test mode still uses the real customer-facing releases with Tito's test_mode
widget. It does not use the old Test Wave releases.
